## 机制与职责

轨迹采集 → 候选评估 → 依据原始证据写经验 → 审核 → 保存项目记忆 → 后续检索复用。

常规轨迹采集并不会自动调用Jev；显式记忆评估才发送有界、经脱敏处理的轨迹投影。Jev判断task_success、reusable_correction、evidence_supported，返回分数而非经验正文。写作agent生成经验，审批后保存在项目范围SQLite memory.db，可通过MCP或项目skill检索。

该版本评估投影最多80个事件，保留前40与后40，标记中间省略；文本字段截断为1200字符。摘要可能丢失决定性证据，生成经验时仍应查看原始轨迹。脱敏不是对所有秘密的保证，真实部署应检查外发内容。

候选准入包含task_success至少0.5且三项均值至少0.6。独立成功门槛可避免失败任务仅凭“经验有用”抬高均分后进入成功经验。默认模型别名jev-latest可能随升级变化，生产评估宜记录返回版本并校准阈值。

## 与Jev Judge及Decisions的关系

[运维证据实验](07-agent-evidence-learning.md)验证的是报告诚信，不等于Beacon经验质量。必须分开记录任务完成、报告与证据一致、经验是否可复用。

[Decisions与Jev比较](08-decisions-jev-comparison.md)建议将judge做成可替换组件。替换judge只改变候选评分；不会自动提供采集、经验写作、审批或检索。拒绝和API异常应留作独立状态，不放行。

## 后续设计建议（尚未实现）

- 分开成功经验与失败教训。失败也可能有价值，但原因必须有证据，不能由模型补猜。
- 保存原始轨迹引用、模型与rubric版本、审批状态、适用条件和失效条件。
- 原始事实优先于评分；平均分不能覆盖已知失败、错误主机或缺失后置检查。
- 用新任务的“有记忆/无记忆”对照评估重复错误、完成率和总成本；session数量仅是规模指标。
- 防止记忆中的错误经验反复传播，提供撤销、更新和失效机制。

核心收获：经验系统的效果取决于证据、准入、撰写、审批和检索整个链条，不能用单次judge高分证明持续学习有效。
